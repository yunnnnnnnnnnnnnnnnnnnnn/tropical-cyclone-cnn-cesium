# 成员B全部任务和注意事项

基于中国气象局台风最佳路径数据集的 CNN 与 Cesium 项目

成员B负责将成员A确认的预测结果接入Cesium系统，形成可操作、可解释、可稳定演示的三维平台。

## 一 工作边界

**项目统一定位：**本项目基于中国气象局台风最佳路径数据集，利用台风历史轨迹、强度等级、近中心最大风速及移动趋势特征，构建轻量化深度学习预测模型，并结合 Cesium 实现台风路径、强度变化和影响范围的三维动态可视化。

**工作量原则：**约25%：Vue 3、TypeScript、Cesium系统和演示交互主责。

## 二 使用平台

| 工作内容 | 推荐平台与工具 | 使用要求 |
|---|---|---|
| 前端开发 | VS Code，Node.js，npm 或 pnpm | 锁定依赖版本并提供启动命令 |
| 三维可视化 | Vue 3，TypeScript，CesiumJS | 历史、预测和范围图层分开管理 |
| 接口联调 | JSON，浏览器开发者工具 | 按成员A定义的字段和时间格式接入 |
| 演示验证 | Chrome 或 Edge | 完成离线演示与基本异常测试 |

## 三 系统基础与接口

成员B承担约25%的工作量，负责Vue 3、TypeScript和Cesium展示系统，保证模型结果可交互呈现。

- 整理现有系统目录、启动方式、依赖版本和离线演示方式。
- 根据队长接口规范接收历史轨迹、预测轨迹、强度、风圈和预测范围数据。
- 区分历史实况、模型预测和统计范围，使用明确图例、颜色和文字标签。
- 优先保障离线历史回放，不把未接入的实时接口展示为实时功能。

## 四 核心可视化功能

系统应围绕台风路径、强度变化和影响范围形成清晰演示链路。

- 完成历史轨迹和预测轨迹的三维显示，并突出预测起点和未来6、12、24小时节点。
- 接入台风筛选、时间轴动画、点位查询、图层开关和基本数据面板。
- 按实际字段绘制风圈或影响范围；参数来源不明确时使用说明文字，不伪造物理含义。
- 如队长提供了经误差统计得到的预测范围，显示为预测走廊并标注其统计来源。
- 删除截图和界面中的Email、Union Ads、Video Ads等无关模板内容。

## 五 联调与演示稳定性

成员B负责系统能在规定环境中稳定演示，所有视觉数字与结果表保持一致。

- 准备至少一个稳定移动、一个转向或强度变化明显的典型案例。
- 检查时间轴、图表、地图点位和预测JSON的时间是否对齐。
- 完成加载失败、空数据、非法字段和浏览器刷新等基本异常处理。
- 记录启动命令、浏览器要求、数据目录和演示步骤，交给成员C写入运行说明。

## 交付物和完成标准

| 交付物 | 必须包含 | 完成标准 |
|---|---|---|
| 可运行系统 | Vue 3 + TypeScript + Cesium项目和依赖说明 | 按运行说明可启动 |
| 接口接入版本 | 预测JSON、图例、时间轴和图表 | 历史与预测状态清楚 |
| 演示案例 | 典型台风、操作步骤、截图和录屏素材 | 第19天完成稳定流程 |
| 运行说明 | 环境、命令、目录、常见问题和离线数据 | 成员C可直接编入提交包 |

## 注意事项

- 不要把统计预测区间直接称为真实概率，也不要使用没有计算依据的概率锥体说法。
- 不要伪造实时数据；系统界面应标注离线历史回放或准实时原型。
- 经纬度、风速、风力等级和时间格式必须与模型输出及作品方案完全一致。
- 所有地图图层应能关闭或切换，避免历史轨迹、预测轨迹和范围叠加造成误读。
- 演示前清理测试账号、模板图表、调试日志、外部链接和无关界面元素。

## 交接要求

- 所有代码、数据处理脚本、实验记录和素材使用统一命名，并在提交前写明版本日期。
- 涉及指标、单位、样本量和预测时效的内容必须以队长确认的结果表为准。
- 任何未实现功能不得在作品方案、答辩PPT、视频字幕或系统界面中表述为已完成。
